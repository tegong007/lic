## 重要 Bug 修复：Mock 拦截点错误导致首页请求绕过 mock（两次迭代）

**现象**：`.env` 已设 `VITE_MOCK_ENABLED=true`、mock 数据也造了故障态，但首页设备状态仍显示"离线"。

**第一轮（错误假设）**：以为只重写 `service.post` 漏了 `service(config)` 调用，改去重写 `service.request`。
**第二轮（真正根因）**：axios 1.11 中 `service(config)` 调用的是 `Axios.prototype.request` 的原始绑定，**根本不会查 `service.request` 属性**；同理重写 `service.request` 也拦不到 `service.post`（post 内部走的是 `context.request` = 原型方法）。所以无论重写 `.post` 还是 `.request` 都无效。

**正确修复**：在 **adapter 层**拦截 —— `service.defaults.adapter = mockAdapter`。所有请求方式（service(config)、service.post、service.get）最终都经过 adapter 层，这是唯一能一网打尽的关卡。命中 mock 返回 `{data:{code,respData,msg}, status:200,...}`（经 response 拦截器解包）；未命中则 `service.request({...config, adapter: REAL_ADAPTER})` 委托真实 adapter（xhr/http/fetch，默认 `['xhr','http','fetch']`）。

**验证**：写临时 node 脚本，对 `service({url,method})` 与 `service.post(url)` 两种方式各发一次请求，确认自定义 adapter 的 hits 数组包含两条 URL 且返回都被 response 拦截器正确解包 → 方案成立。

**经验**：

- 改 `.env` 或 `setup.ts` 后必须**重启 dev server**（`import.meta.env` 与 `enableMock()` 都在启动时执行，HMR 不可靠）。
- axios mock 拦截正确姿势 = 自定义 adapter，不是重写 `.post`/`.request`。

## App 布局约定（页面内容需避开绝对定位 Header 与固定 Footer）

- `App.vue` 的 `<Header>`（`TheHeader.vue`）是 `position: absolute` 浮在顶部，约占用顶部 10vh（系统名 3.4vw line-height 9.5vh + 网络/时间行）。
- `<Footer>`（`TheFooter.vue`）是 `fixed bottom`，底部导航按钮高 7vh + 1vh 间距，约占用底部 8~9vh。
- router-view 是 flex:1，因 Header/Footer 都脱离文档流，router-view 实际高度≈100vh。
- 所以 main route 页面若用 `absolute inset-0` 铺满，会同时被 Header（顶部）和 Footer（底部）压住内容。正确做法：用 `relative h-100vh` + `pt-[10vh] pb-[9vh]`，再用 `flex flex-col justify-between` 分布上中下三段（参考本次 MachineErrorPage 的修正）。
- 非 main route 页面（如 `/login`）默认不渲染 Header/Footer；若想让某页也显示系统头部栏，直接在该页 `<template>` 内引入 `<TheHeader />`（不要把它加进 `mainRoutes`，否则底部导航按钮也会一起出现）。
