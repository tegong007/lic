## 迭代修正（用户反馈 5 点）

**1. mock 双层 respData 导致数据不展示（关键 bug）**
`findMockResponse` 内部已统一包装 `{ code: 0, respData: handler返回值, msg }`。我在 handler 里又写了 `return { respData: [...] }`，导致最终结构是 `{ code:0, respData:{ respData:[...] } }`，页面 `Array.isArray(data.respData)` 为 false → 表格和图片全空。**handler 必须直接返回业务数据本身**（数组/对象），不要再包 respData。

**2. mock 参数在 adapter 阶段已序列化**
axios 在调 adapter 前执行 transformRequest，`config.data` 已是 JSON 字符串。所以 `params?.moduleUid` 取不到，只能 fallback 默认值。修法：handler 内 `typeof params === 'string'` 时先 `JSON.parse`。

原显示「1模块错误处理」，改为中文数字：新增 `CN_NUM` 数组 + `moduleCn` computed，输出「模块一错误处理」。

**4. 模块细节图标红逻辑（m1/m2 已定，m3/m4/m6 待补）**

- `imageItems` computed：单图模块（m2/m5/m7）→ 只渲染一张，有工位 `code !== 0` 则整块标红；双图模块（m1）→ 渲染 top+bottom，`errorUids` 含 `M1_SLEW_JOB` 时 bottom 标红，含其他出错 uid 时 top 标红。
- 标红方式：`.img-item.is-error::after` 绝对定位盖 `rgba(180,5,5,0.55)`。

**5. 表格样式改回原生 table（项目不用 antd Table）**

## 第六次修正（背景图 + 图片栏缩窄）

**根因**：ModuleErrorHandlePage 根 div 没设背景，加上 App.vue 的 `<transition>` 让组件 `position:absolute` 浮在父容器上，把 App.vue 的 `.bg` 类背景遮住 → 看起来是浏览器默认深色而不是 `bg.png`。

**修复**：根 div inline style 加 `background: url('@/assets/image/bg.png') center / 100% 100% no-repeat`，让页面铺满项目默认背景。

**关键经验**：所有通过 router-view 渲染的页面组件（被 fade transition `position:absolute` 影响）都要在根 div 自带背景，不能依赖 App.vue 父容器 `.bg` 的传递。HomePage/LoginPage 用 `.bgT` 装饰图、`bgT` 在 scoped 里定义；其他新页面要自己加 background inline style 或 :style 绑定。

**图片栏宽度** 30% → 22%，让右侧表单区更舒展。

**背景最终方案（用户确认 tmp_lr.png）**：HomePage 视觉是「App.vue 全局 `bg.png` 铺满打底 + `.bgT` 用 `tmp_lr.png`（contain）装饰叠加」两层，所以根 div 用多层 background：
`background-image: url(tmp_lr.png), url(bg.png); background-size: contain, 100% 100%; background-repeat: no-repeat, no-repeat; background-position: center, center;`
只写 tmp_lr.png + contain 会留白露底色。**多层 background 用逗号分隔，前面的图层在上层。**

## 第七次修正（行高 / sticky 表头 / 表格上下边距）

- `.list-row` 行高：`padding: 1vh → 0.75vh`、`margin: 0.5vh → 0.4vh`（更紧凑）

**注意**：用户会自己手动微调样式（如 `.add-btn` 高度/圆角、`.footer` 对齐方式），后续改动要尊重用户已调好的值，只改用户明确要求的部分。
